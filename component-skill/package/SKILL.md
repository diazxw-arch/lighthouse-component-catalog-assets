# Lighthouse catalog component builder

Version **1.0** · 30 verified new components per review · next version **1.1**.

Create the real component, publish it in the actual catalog, and preserve its reference media. Start with one requested ID or an explicitly assigned eligible batch. This skill does not start research, image generation, old workers, or automations.

## Restore before building

Honor the latest human Stop/Pause and ownership. Read the current assignment, production rules, scoped corrections, owner checkpoint and acceptance entry. Reconcile commands completed after the checkpoint. Write the exact unfinished step and next IDs before continuing. A closed hover fix is not a new objective. Reuse valid proof for unchanged inputs; never refresh an observation timestamp without observing again.

Read [workflow](references/workflow.md) for the relevant stage and [known errors](references/known-errors.md) before that family. Use Apple Design within the reference geometry and current Lighthouse guidance; retain authored type, wording, media and colors. Scope corrections to their affected components and explicit exceptions. Use the piece-builder only when the actual task involves Layout Maker pieces.

## Deliver a component

1. Inspect the original, selected Image Gen version, catalog manifest, existing implementation and acceptance hashes. Missing Image Gen stays waiting. Already accepted unchanged work is reused.
2. Reuse suitable typed primitives and installed dependencies. Implement reusable controlled UI and real host callbacks. Preserve sandbox/security, accessibility, original artwork and font licenses.
3. Compare the rendered result to the references. Check interactions, keyboard/focus, error/empty/disabled states, overflow and responsive widths, including the actual catalog iframe. Record actual observations and residual differences per ID.
4. Work in coherent batches of 5, up to 10. Run targeted checks while editing and one required independent review/build/CI/deploy cycle per batch. Recheck changed paths; preserve valid unchanged proof. A local pass, production pass, catalog pass and cleanup are separate states.
5. Commit, push, integrate, deploy and verify the exact production component and actual catalog under the existing release authorization. Respect a later local-only or Stop instruction. Retire FigCraft mocks only after replacement verification, dependency/active-writer checks and recoverable retention.
6. Record completion with the reviewed [cycle tracker](references/measurement.md). Only distinct newly accepted components count. Never count baseline deliveries, fixes, state variants or partial batches. Save the next concrete step and stop owned temporary children.

## Evolve after 30

Record measured time, rework, first-pass quality and evidence for each delivery. At **30**, the tracker blocks further completion records until the workflow review advances the version by **0.1**. Compare similar component families; adopt only methods with measured benefit and no quality/gate regression. Document known errors and retained methods even when no replacement is better. Update this package, changelog, manifest, website and installed copy through static inspection and tests before starting the next cycle. No timer or background restart is needed.

Follow [measurement and release instructions](references/measurement.md). Unknown timing remains unknown. Do not invent speed, fidelity or acceptance claims.
