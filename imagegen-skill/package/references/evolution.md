# Hourly evolution without production pauses

The human changed skill reviews from every10 entries to every one hour. The parent performs one evidence-based review each hour while the sole worker continues its assigned private production. Review due is never a production or counting gate. After interruption, do one current overdue review; do not fabricate missed releases. Each actual reviewed release increases the version exactly0.1 (1.9→2.0). Keep the last approved version when a release is blocked, record the blocker and continue independent authorized production.

The parent records each entry's preparation, awaited ImageGen calls, correction, inspection, registration/readback, orchestration waits and timing unknowns. Preserve original/raw/stored hashes, actual displayed-size and enlarged quality observations, exact workflow version, attempts and parent-versus-worker ratings. Include deferred cases, failed calls and review overhead when evaluating overall throughput, with separate denominators from ready accepted entries. Report comparable sample counts, median/p90 time per accepted entry, first-pass acceptance, retries, visible defects and accepted entries per measured hour. Do not estimate unknown active time or call a mixed small sample a speedup.

Prioritize the largest observed bottleneck. Reuse unchanged setup/evidence, inspect original artwork/icon anatomy, and compare output at intended size before rejecting scale. Separate raw canvas padding from actual content geometry. The two-call and ready-only acceptance gates remain. The worker never approves itself, edits the skill, or publishes. Parent catalog/image batches remain every30 accepted entries; skill guide/package updates occur hourly independently of that batch.

Stage each release outside active discovery, test affected behavior, complete mandatory SkillSpector --no-llm and source-aware review of exact runtime/package, then install only approved bytes. Publish and verify its matching skill guide, package and aggregate metrics through current-source Sites, preserving other routes and private evidence. Write the real review receipt after public verification. Never mark a failed/unseen/pending result ready to improve a metric.

## Explicit hourly ledger migration

Schema2 and prior entry/review attestations remain immutable history. Back up the ledger, then prepare an owner migration JSON with expectedLedgerDigest=SHA256(JSON.stringify(original ledger)), at=explicit timezone timestamp, and reason=the direct human cadence change. Run node scripts/learning.mjs migrate-hourly --ledger <private-ledger> --receipt <migration-receipt> --backup <original-backup>. It compares the backup under the existing exclusive lock and validates the old schema before writing schema3. The historical ledger, rows and reviews remain digest-bound. The first human-requested release may happen immediately; subsequent release timestamps must be at least one hour apart. Release timestamps cannot be ahead of the actual command clock.

Schema3 records ready entries without a count ceiling. Reports show lastHourlyReviewAt, nextHourlyReviewAt and reviewDue, with productionBlockedByReview=false. Each hourly receipt includes through=actual reviewed snapshot count, entriesDigest=SHA256(JSON.stringify(entries.slice(0,through))), reviewedAt, version, decision(retain/improve), rationale, packageSha256, and actual errorsReviewed/timingReviewed/qualityReviewed/testsPassed/scanPassed/sourceReviewPassed/websitePublished flags. Metadata uses reviewIntervalMinutes60 and completedEntriesAtRelease equal to the reviewed snapshot, not a count-derived version.

Concurrent private work may finish under the immediately previous version only when its startedAt precedes that version's real retirement timestamp. Preserve that attestation; a task cannot claim a version before its activation timestamp. The legacy initial version retains an unknown lower start boundary, explicitly. New starts use the current version. Do not rewrite old receipts. The first review can cover zero new accepted entries when evidence is failures or overhead; that is not completion credit. The recorder never resets attempts or approves registration.

Only sanitized aggregates belong on the website. Keep prompts, screenshots, worker IDs, private paths and notes local. Human Stop/Pause remains immediate.
