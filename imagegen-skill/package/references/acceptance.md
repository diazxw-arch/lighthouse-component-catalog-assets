# Parent acceptance contract

Failed outputs stay in the private attempt directory. They must not be copied into the public catalog, given a version, recorded as a new completion or used to advance a batch. A two-call failure produces a method-blocker note and a parent decision, not needs-correction registration.

An assignment supplies catalogRoot, managerThreadId, workerThreadId, entries and skillReview.productionHold=false. The parent releases that hold only after the required review. It retains authority to stop at any time.

Parent creates .local/.../manager/approvals/<entryId>.json after actual original/native/candidate inspection. Required fields: entryId, parentThreadId, candidateSha256, targetFrame{width,height}, status=reviewed, five quality values3–4 with protectedMedia=4, defects=[], residuals=[], promptSha256, referencesSha256, references[{path,sha256}] for original/native evidence, and evidence{originalCompared,intendedSizeCompared,enlargedCompared,originalsUnchanged,rawUnmodified,protectedMediaExact}=true.

The approval and job are explicit local files. Actual hashes and PNG frame are checked. Target aspect allows at most2% relative deviation for tool sampling; inspect spacing/type independently. No aspect tolerance permits a materially wrong layout. For a deliberate viewport/native difference, the parent must first establish the real target from source evidence; do not widen tolerance to pass a failed candidate.

The worker prepares job fields entryId, assignmentPath, catalogRoot, candidatePath, promptPath, referencesPath, approvalPath. Use register-ready.mjs check first, then register. The helper remains outside this package and must be the existing catalog-owned 画像生成を登録.mjs in the exact assigned catalogRoot. The wrapper uses the current Node interpreter, structured arguments, no shell and a hidden Windows child. No uploads occur here. Actual helper stdout/readback still needs inspection.

The gate cannot establish visual truth from booleans, authenticate authors against a malicious same-user process, or prevent arbitrary manual legacy commands. Parent-owned approvals, explicit assignment and output inspection remain mandatory. The worker must never author or fabricate approval. A valid gate is necessary, never sufficient proof of fidelity.

A new learning receipt includes acceptanceJob; the CLI rechecks its current approval and bytes. New needs-correction records are rejected. Existing failed rows remain unchanged as historical processed work. Report ready progress separately and do not represent the historical26 processed entries as26 finished components.

Before register, the wrapper verifies assignment.catalogRuntime registrationHelperSha256 and managementHelperSha256 against the reviewed existing helper bytes. A duplicate stored hash with a non-reviewed status is rejected rather than silently promoted. After register and again before learning record, actual stored PNG/metadata/manifest/canonical catalog status, hash, version, displayed version and parent quality are read back. Claimed receipt flags cannot replace this readback.

For reviewed duplicates, stored prompt text and ordered inputReferences must equal the approved job before registration/readback. A new prompt cannot be retroactively attached to old bytes by replay. Preserve original attempt/time provenance and use explicit parent recovery if metadata differs.

Approval also records attempts (1 or2). The two-call maximum is checked before register and before a new learning record; an exhausted failed entry stops. assignment.catalogRuntime.files pins the reviewed local import/refresh closure, including the updater and its four local modules. Dependency changes require renewed inspection.
